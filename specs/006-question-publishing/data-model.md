# Data Model: Question Creation and Publication Flow

## Existing Persistent Entities

This specification reuses the `Question`, `Answer`, and `User` schemas from SPEC 005 and adds no migration or persistent columns.

### Question

| Field | Type | Mutability | Rule in This Specification |
| --- | --- | --- | --- |
| `id` | string | Immutable | Generated uniquely when creating a draft. |
| `creatorUserId` | string | Immutable | User ID of the authenticated Human. |
| `body` | string | Draft only | 10–1,000 grapheme clusters after trimming. |
| `language` | string | Internal compatibility only | Retained for existing-schema compatibility. New Questions store `auto`; it is not used in user input, display, or WebMCP contracts. |
| `publishedAt` | UTC Unix milliseconds or null | Once at publication | Null means Draft. Set to service-side `now` at publication. |
| `closesAt` | UTC Unix milliseconds | Draft only | From `now + 1 hour` through `now + 30 days` at save, edit, and publication. |
| `revealsAt` | UTC Unix milliseconds | Draft only | Always equal to `closesAt`; not user input. |
| `createdAt` | UTC Unix milliseconds | Immutable | Service-side `now` when creating the draft. |
| `updatedAt` | UTC Unix milliseconds | On draft edit and publication | Also used for optimistic conflict detection. |

### Answer

This specification neither creates nor retrieves Answer content. `My Questions` aggregates only the count for each Question and returns no body, excerpt, or `userId`.

### User

The authentication subject managed by Better Auth. Only the `user.id` obtained from the Session is used to determine Question creator and ownership.

## Non-Persistent Input and Display Models

### QuestionDraftForm

| Field | Source | Required | Rule |
| --- | --- | --- | --- |
| `body` | textarea | yes | 10–1,000 graphemes after trimming; redisplay the value on error. |
| `closesAtLocal` | `datetime-local` | yes | Local date/time confirmed by the User; not persisted. |
| `closesAt` | hidden | yes | UTC Unix milliseconds generated by the client and range-validated again by the server. |
| `timeZone` | hidden/display | yes | IANA time-zone name used for confirmation display, not state evaluation. |
| `contentAcknowledged` | checkbox | yes | Self-attestation regarding public, personal, confidential, and harmful content; not persisted. |
| `expectedUpdatedAt` | hidden | required when editing | Loaded draft's `updatedAt`, used to detect conflicting updates. |

### ValidatedQuestionDraft

Internal application value that passed the input contract.

| Field | Type | Meaning |
| --- | --- | --- |
| `body` | string | Body with surrounding whitespace removed. |
| `language` | `auto` | Internal compatibility value stored in the existing schema; not an answer-language selection. |
| `closesAt` | number | Validated UTC Unix milliseconds. |
| `revealsAt` | number | Equal to `closesAt`. |

### QuestionFormErrors

Contains at most one English message for each of the `body`, `closesAt`, `contentAcknowledged`, and `form` keys. The screen connects messages to inputs with `aria-describedby` and `aria-invalid`, and each field is reachable from the error summary at the top.

### OwnedQuestionSummary

| Field | Source | External Display |
| --- | --- | --- |
| `question` | Question owned by the current User | Beginning of body, state, deadline, and state-specific actions. |
| `answerCount` | Answer aggregate | Numeric count only; excludes Answer content and submitter. |

## Relationships and Boundaries

```text
Authenticated User 1 ─── 0..* owned Question
Question 1 ─── 0..* Answer ── count only ──> OwnedQuestionSummary
QuestionDraftForm ── validate(now) ──> ValidatedQuestionDraft
ValidatedQuestionDraft ── create/update ──> Question(DRAFT)
Question(DRAFT) ── publish(now) ──> Question(OPEN)
```

- Management retrieval always filters by `question.id + creatorUserId`.
- Externally, Questions owned by someone else and nonexistent Questions are both treated as unavailable.
- Answer aggregation is associated only with the owner's Question list and does not pass Answer-owner information into the display model.

## Input State Transitions

```text
New Form
  ├── invalid ──> New Form + field errors + preserved values
  └── valid ────> DRAFT

DRAFT
  ├── valid edit + matching updatedAt ──> DRAFT(updated)
  ├── stale edit / already published ──> conflict, no overwrite
  └── review + explicit publish
        ├── valid at execution time ────> OPEN
        └── invalid/stale ──────────────> DRAFT or latest state, no publish

OPEN/CLOSED/REVEALED
  └── edit or publish ──> rejected, stored values unchanged
```

## Repository Operations

| Operation | Primary Condition | Success Result | Stable Failure Classification |
| --- | --- | --- | --- |
| `createDraft` | Creator exists, validated input | `created` | `creator-missing`, `invalid`, `unavailable` |
| `getOwnedQuestion` | ID and creator match | Question | `null` (combines missing and other owner) |
| `updateDraft` | ID, creator, Draft, and expectedUpdatedAt match | `updated` | `unavailable-to-owner`, `conflict`, `invalid`, `unavailable` |
| `publish` | ID, creator, Draft, deadline in range, close=reveal | `published` | `unavailable-to-owner`, `invalid-transition`, `unavailable` |
| `listByCreator` | Creator matches | `OwnedQuestionSummary[]` | `unavailable` |

Routes map the repository's internal classifications to the external responses in the [Question management contract](contracts/question-management.md).
